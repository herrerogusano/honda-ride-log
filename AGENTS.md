# Agent guide

Static web (Vite + TypeScript, no framework) that shows a rider their own
route statistics. It is a browser client of a separate invitation-only
service; it has no backend. **Read `docs/PLAN.md` first**: it holds the
decisions, the privacy rules, the design and the checked and unchecked
technical facts.

## Hard rules

- This repository is public. Never commit personal data, real
  identifiers (route ids, plates, VINs, emails, coordinates of real rides),
  tokens or anything copied from a real account. Fixtures are synthetic and
  generated by `src/demo/`. One exception, by the owner's decision: the
  `production` entry of `environments.config.json` holds the three public
  values of the production service (address, login domain, web client id).
  Values of any other deployment stay out of the repository.
- Privacy rules in `docs/PLAN.md` are requirements, not suggestions. Data
  from the service goes through `src/domain/sanitize.ts` before anything else
  touches it.
- No analytics, no third-party requests except OpenStreetMap tiles. The
  Content Security Policy lives in `csp.config.json`; changing it needs a
  written reason in `docs/PLAN.md` and a matching change in
  `tests/csp.test.ts`.
- No `innerHTML` or other HTML-string sinks, no inline scripts, styles or
  handlers. No browser storage, with two one-file exceptions recorded in
  `docs/PLAN.md`: `src/storage/maintenance.ts` may use `localStorage` (and
  only `localStorage`) for the two service-interval numbers the user types,
  and `src/auth/pendingLogin.ts` may use `sessionStorage` (and only
  `sessionStorage`) for the PKCE verifier and the `state` while the browser
  goes to the login page and back, imported only by `src/auth/login.ts`.
  Never a token. A change that needs another exception opens it for a single
  file, records it there and in `tests/lint-storage.test.ts`.
  (ESLint and `scripts/check-dist.mjs` catch the common forms; they are a
  net, not a proof).
- Route ids and untrimmed traces are sealed handles. Do not widen the
  ESLint import rules that guard `serviceRouteId` and `untrimmedLines`.
- Runtime dependencies: Leaflet only. Charts are hand-written SVG.
- User-facing text is Spanish. Code, comments and commit messages are English.

## Commands

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build   # typecheck + vite build + publication checks on dist/
```

## Process

- Small pull requests against `main`; CI (lint, tests, build) must be green
  and an independent reviewer must have looked at the change before a
  merge: PullBeacon (comment `@pullbeacon review` on the PR; review only,
  `.pullbeacon.yml`) reads the diff, and a browser check at phone and desktop
  widths covers what it cannot see. Changes to privacy, data or sign-in code
  also get a reviewer agent that runs the tests and breaks the code on
  purpose. No direct pushes to `main`.
- Every new test must be seen failing once with broken data before it counts.
- A green test against a fake proves the contract as we read it, not that
  the real service behaves that way. Say which one you ran.
