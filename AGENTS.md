# Agent guide

Static web (Vite + TypeScript, no framework) that shows a rider their own
route statistics. It is a browser client of a separate invitation-only
service; it has no backend. **Read `docs/PLAN.md` first**: it holds the
decisions, the privacy rules, the checked and unchecked technical facts and
the phase split.

## Hard rules

- This repository is (or will be) public. Never commit personal data, real
  identifiers (route ids, plates, VINs, emails, coordinates of real rides),
  tokens, client ids of a real deployment or anything copied from a real
  account. Fixtures are synthetic and generated by `src/demo/`.
- Privacy rules in `docs/PLAN.md` are requirements, not suggestions. Data
  from the service goes through `src/domain/sanitize.ts` before anything else
  touches it.
- No analytics, no third-party requests except OpenStreetMap tiles. The
  Content Security Policy lives in `csp.config.json`; changing it needs a
  written reason in `docs/PLAN.md` and a matching change in
  `tests/csp.test.ts`.
- No `innerHTML` or other HTML-string sinks, no inline scripts, styles or
  handlers. No browser storage, with one exception recorded in
  `docs/PLAN.md`: `src/storage/maintenance.ts` may use `localStorage` for the
  two service-interval numbers the user types; a phase that needs another
  one opens it for a single file and records it there.
  (ESLint and `scripts/check-dist.mjs` catch the common forms; they are a
  net, not a proof).
- Route ids and untrimmed traces are sealed handles. Do not widen the
  ESLint import rules that guard `serviceRouteId` and `untrimmedLines`.
- Runtime dependencies: Leaflet only. Charts are hand-written SVG.
- User-facing text is Spanish. Code, comments and commit messages are English.

## Commands

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build   # typecheck + vite build + publication checks on dist/
```

## Process

- Small pull requests against `main`; CI (lint, tests, build) must be green
  and an independent reviewer agent must have looked at the change before a
  merge. No direct pushes to `main`.
- Every new test must be seen failing once with broken data before it counts.
- A green test against a fake proves the contract as we read it, not that
  the real service behaves that way. Say which one you ran.
